## 1. フォルダを確保する

接続フォルダを確認する（`ls $HOME/mnt/` ／ `device_list_dir`）。
接続されていなければ、**オーナーに手順を説明せず自分で `device_request_folder_access` を呼ぶ**。
承認ダイアログを押してもらう。パスが分からない時だけ1問で聞く。

その環境に初めて置く場合:

```bash
git clone git@github.com:akiyoshiyosuke/lask.git lask
```

※ フォルダ名とリポジトリ名は一致しなくてよい。最初のマシンではフォルダ名が
`究極のタスク管理サービス` になっている。


`git status` が汚れていたら、先に何が変わっているかを読んでから進める。

## 6. 締める（未 push を残さない）

**未 push の変更を手元に残したままセッションを終わらせない。衝突はそこからしか生まれない。**

```bash
git status                      # 身に覚えのない変更が混ざっていたら止めて報告する
git add <ファイル名を明示>        # add -A / commit -a は使わない
git commit -m "<何を、なぜ>"
git push -u origin feat/<やること>
```

main に入れるのは**オーナーの合図があってから**:

```bash
git switch main && git pull --rebase
git merge --no-ff feat/<やること>
git push
```

締めの報告に必ず書く:
- どのブランチ／コミットを push したか
- main に入れたか、まだか
- 未 push の物が残っていないか（残っていたらその場で push する）

調べた資料・引き継ぎメモも含め、**そのセッションで作った物は全部 push してから終わる**。

## 7. 複数の Claude が同じリポジトリを触るときの約束

- 1セッション＝1ブランチ。他セッションのブランチに乗らない
- 触る前に `git fetch --all && git branch -r` で他所で進んでいるブランチを見る
- `docs/ログ.md` は**末尾に追記**。途中に差し込まない（衝突を作らないため）
- 本体モックを直すのは `ui/lask-home.html` だけ。`ui/lask-25.html` には波及させない
- push 済みの履歴を書き換えない（`rebase -i` / force push しない）
- 名前・識別子・課金が発生する物を勝手に決めない。候補を出してオーナーの一言を待つ

## 8. 認証（環境ごとの違い）

| 環境 | git の認証 |
|---|---|
| Mac のターミナル／Claude Code | `~/.ssh` の鍵でそのまま通る |
| Cowork（デスクトップアプリ内の Linux VM, `device_bash`） | VM はセッションごとに作り直されるので `~/.ssh` が無い。下記の鍵を使う |

Cowork から push する場合は、リポジトリ内の `.gitsecrets/id_ed25519`（git 管理外の deploy key）を使う。
**このフォルダでは `.git/config` の `core.sshCommand` に設定済みなので、何もせず `git push` が通る。**

別のフォルダに clone して Cowork から push したい時だけ、その clone で一度:

```bash
git config core.sshCommand "ssh -i $PWD/.gitsecrets/id_ed25519 -o IdentitiesOnly=yes"
```

（`.gitsecrets/` は git に入らないので、鍵は別途コピーしてくる）

`.gitsecrets/` が無く push できない環境では、**commit まで済ませ「未 push のコミットがある」と
明記して終える**（黙って終わらない）。
鍵の中身を echo / ログ / チャットに出さない。
